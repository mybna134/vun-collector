# Production code change workflow

When a new task requires changing production code, create an OpenSpec change proposal before implementation. The proposal must describe the problem, intended behavior, relevant specification changes, and an implementation task list.

Present the OpenSpec proposal to the user for review and wait for their explicit approval before modifying production code. Until approval, limit work to discovery and preparing or revising the OpenSpec artifacts. After approval, implement the approved change through the OpenSpec workflow.

This approval gate applies to new features, bug fixes, refactors, and other changes to production code. It does not apply to documentation-only changes or test-only changes that do not modify production code.
