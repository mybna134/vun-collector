# Design

## Context

仓库目前只有 OpenSpec 配置，没有 Android 工程或既有数据。需求、可观察行为见 `proposal.md` 和三个新增规格。设备可能缺少指定传感器；GPS 与传感器回调的实际频率由硬件和系统决定。

## Goals / Non-Goals

**Goals:**

- 从零建立可安装的原生 Android 应用，支持持续采集、本地查看、编辑和 JSON 导出。
- 保留真实事件的时间和值；在大量采样点情况下仍能稳定写入和浏览。
- 让采集权限和数据源状态直接反映在界面上。

**Non-Goals:**

- 云同步、账号、地图轨迹绘制或自动上传。
- 为缺失的类型 3 方向传感器合成方位值。
- 将 GPS 位置强行插值为严格 1 Hz。

## Decisions

### 1. 应用结构与兼容性

使用 Kotlin、Jetpack Compose、单个 Android app 模块、ViewModel 与 Room；最低支持 Android 10（API 29）。记录列表、采集页和详情页由 Compose 实现，采集逻辑放在前台服务中，页面从同一数据源观察最新状态。这样锁屏和页面切换不会销毁采集器。相较于仅在 Activity 中监听，前台服务能维持用户可见的长时间采集；最低 API 29 简化计步权限处理。构建脚本采用 Gradle Kotlin DSL，依赖版本在实施时选可用的稳定版本并固定。

### 2. 数据源与采样时间

按用途使用 `Sensor.TYPE_ACCELEROMETER`(1)、`TYPE_GYROSCOPE`(4)、`TYPE_ORIENTATION`(3)、`TYPE_STEP_COUNTER`(19) 和 `TYPE_STEP_DETECTOR`(18)。原需求将 18/19 的用途写反；以 Android 官方定义和用户描述的语义为准。连续传感器注册 `SENSOR_DELAY_UI`，原样记录每次实际回调。GPS 使用 `LocationManager.GPS_PROVIDER` 请求最短 1000 ms、最小位移 0 m 的更新；仅存实际返回的新 fix。

传感器事件时间用 `SensorEvent.timestamp` 的单调时钟与采集时记录的墙上时钟锚点换算为 UTC epoch 毫秒。GPS 使用 `Location.time`，同时保存精度。每个采样点有稳定 ID，可编辑的时间字段是导出和详情采用的时间。额外保存原始事件时间用于追溯，但编辑后的时间是当前有效值。传感器单位随类型固定，位置字段单独存储。

### 3. 会话、计步基线与持久化

Room 建立 `recordings`、`sensor_samples`、`location_samples` 三张表，采样表通过外键归属记录；删除记录时级联删除采样点。记录含名称、备注、状态、起止时间和各源可用状态。服务只允许一个活动记录；停止时解除监听并把队列写完。回调先复制必要字段到内存队列，由单一写入协程分批入库，避免在传感器回调线程执行磁盘 I/O。崩溃恢复时将仍标为活动的旧记录改为已中断，已入库数据保留。

累计计步保留每个原始读数，显示和导出中的会话相对步数按时间顺序计算：首点为 0；原始值下降时开始新基线段，并将上一段累计值加入偏移。修改累计计步点后重新计算该记录的派生步数；不将单步事件混入累计序列。这样重启设备或编辑点后仍能得到一致、非负的会话值。

### 4. 前台服务与权限

用户从可见页面启动服务，服务立即显示持续通知，包含返回应用和停止操作。按 Android 前台服务规则声明 `health` 和按需启用的 `location` 类型及其权限；`health` 类型使用清单中的 `HIGH_SAMPLING_RATE_SENSORS` 作为前提条件，但实际采样仍为 `SENSOR_DELAY_UI`。计步源需要 `ACTIVITY_RECOGNITION`，GPS 需要精确位置权限；启动前按需请求，拒绝后仍可采集其他源。每次开始前检查传感器与定位源，并在权限或提供者状态变化时更新状态。服务仅从可见页面启动，以满足位置前台服务的启动限制。

### 5. 浏览、编辑和导出

列表查询记录摘要；详情按数据源分页加载样本，单点编辑表单只展示该类型有效字段。保存前校验经纬度范围、非负精度、有限数值、时间戳及记录状态；编辑在事务内完成，累计计步变化触发派生值刷新。删除须经确认并使用数据库事务。

导出通过系统 `ACTION_CREATE_DOCUMENT` 选择目标 URI；从数据库读取一致的记录快照，流式写出 UTF-8 JSON。根对象包含 `schemaVersion: 1`、记录元数据、源状态和按类型分组的采样数组；每点包含 ID、`timestampEpochMs`、类型、数值、单位和 `edited` 标记，GPS 点包含 `latitude`、`longitude`、`accuracyMeters`。写入失败向用户报告，绝不更新本地记录。文档提供一个 JSON 示例和字段说明。

## Risks / Trade-offs

- [类型 3 方向传感器已弃用，部分设备缺失] → 保留用户指定的类型，不隐式改用其他方向算法；页面明确提示不可用。
- [GPS 的 1000 ms 参数是最短间隔，不保证每秒都有 fix] → 保存真实回调，展示等待状态，导出不补点。
- [高频采样增加电量和存储占用] → 使用指定的 UI 采样档位、批量写入和分页读取；记录停止后立即解除监听。
- [前台服务仍可能被系统终止] → 已提交的样本持久化，恢复时标记中断。
- [用户修改原始样本会影响分析结果] → 给修改过的点打 `edited` 标记，导出当前值并保留原始事件时间。

## Migration Plan

无既有应用或数据需要迁移。实施后构建 APK，在具备相关传感器和 GPS 的设备上验证采集、权限、锁屏、编辑与导出；回退可移除新应用模块和本次新增的本地数据格式。
